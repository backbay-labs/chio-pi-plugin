Nineteen coordinator commands completed successfully with zero command skips.
Individual cases retain raw native invocations and independently observed files
and dispatch rows; a coordinator command is not one acceptance gate. Model
non-attempts on a resumed conversation remain labeled as non-attempts. Where
necessary, the retained driver then used a fresh native conversation under the
same original gateway authority to obtain the actual refusal attempt.

The hung-extension case uses an explicit qualification watchdog. It proves zero
protected dispatch during the hang and after watchdog termination; it does not
claim an automatic extension timeout that the implementation does not provide.

All three storage cases began with a completed, acknowledged native write. The
controller then held a genuine SQLite write lock before admission, after an
effect before receipt persistence, or after an effect before admission-result
persistence. Before-admission failure caused zero new dispatches; the two
post-effect cases caused one original effect each. Every unknown result remained
unacknowledged. Same-action and new-action retries, and a restart of the same
kernel owner, produced no additional dispatch. No rows, clocks, journals or
fences were cleared. The before-admission no-effect observation does not convert
the post-effect cases into prevention claims.

The actual expiry record came from the trusted owner SQLite session record. Its
capability signature was independently checked against its embedded issuer;
that issuer is distinct from the receipt signer. Both policy TTLs were ten
seconds and the test waited for the actual issued expiry. It did not rewrite
capability time or mutate the database. Separate root evidence checks the receipt
trust root and substitution behavior.

Supplemental exact-policy process probes denied private file reads and aliases,
configuration/code writes and hardlinks, subprocesses, direct kernel access and
unrelated network connections, with independent positive controls. A forced
provider two-call fixture used actual Pi and kernel/resource execution: Pi
serialized the calls, the first completed, and the second was refused while the
first result was not yet acknowledged. These are explicitly labeled fixtures,
not live-model acceptance replacements.

Three paired readonly observations recorded six independent dispatches with
unchanged resource bytes. Native Pi tool interval median was 470.309375 ms; direct
bridge interval median was 438.27875 ms. The median paired difference was
-13.723917 ms, illustrating small-sample scheduling variation rather than negative
integration cost. Both routes included bridge verification and kernel execution.
Model generation, preparation, process startup and later ACK were excluded.
These observations establish neither a load benchmark nor a general overhead
claim.

The root coordinator requested a capacity pause after a global 4 GB Colima OOM
in another lane. This Pi lane's active gateway-crash case completed, then no new
stage started until authorization to resume. The original owners were retained;
all captured driver bytes remained unchanged. Raw pause/resume records are
included. Outer command durations spanning the pause are excluded from latency
claims. No Pi case on this binary failed because of that interruption.

All completed Pi kernel owners and their labeled resource containers were
stopped after their final observations. Volumes, authority databases and private
journals remain intact. Ports 59251-59256 and exact owner/volume names are recorded
in the command and owner manifests. Provider credentials, bearer tokens, private
profiles and databases are excluded from committed evidence; the known-secret
scan had zero matches. The earlier installation-preparation failures remain in
